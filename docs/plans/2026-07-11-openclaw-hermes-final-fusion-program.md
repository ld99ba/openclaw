# OpenClaw-Hermes Final Fusion Program

This program replaces the unbounded V1.2/V1.3 framing with one finite objective:
create a final deliverable system that contains OpenClaw capabilities, contains
Hermes capabilities, and adds unified capabilities that exceed either source
system alone.

## Operating Rule

Every follow-up task must answer one question: does this close a final fusion
gap? If it does not, it is out of scope for the final fusion program.

## Completion Model

The final system is complete only when all final fusion workstreams are closed:

- Capability inventory and parity proof
- Hermes capability promotion
- Unified governance kernel
- Memory, skill, and knowledge lifecycle
- Recovery and autonomous execution
- Installable and operable product
- Beyond-both-system capabilities

## Immediate Work

The next concrete step is a source-anchored capability inventory for OpenClaw
and Hermes. That inventory must map each capability to its source evidence,
OpenClaw owner, test surface, acceptance gate, and final status.

## Boundaries

- Do not create a new version ladder.
- Do not claim final fusion from adapter or migration evidence alone.
- Do not freeze the current baseline as final until all fusion gaps are closed.
- Do not mutate tags, releases, or pull requests in this alignment step.
